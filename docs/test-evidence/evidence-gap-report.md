## Evidence Quality Risks

- Generated evidence files under `docs/test-evidence/generated` are useful summaries, but they are not a substitute for command outputs from the target stack.
- The Node evidence pack can remain green while target parity is still incomplete.
- Structural tests can confirm files and route declarations, but they do not prove runtime behavior, transaction boundaries, restart survival, or authorization enforcement.
- Audit hash-chain appends now use a PostgreSQL lock row for concurrent API smoke paths, and staff approval execution, staff audited customer detail, customer transfer commands, FDS/AML decision request creation, plus reconciliation adjustment request creation have bounded SERIALIZABLE retry for transient command-approval conflicts. Broader bank-grade command paths still need explicit retry or operator-visible failure policies for other serialization conflicts.

## Recommended Next Evidence Slice

The next smallest safe evidence slice is workflow and operational hardening:

1. Broaden workflow orchestration, retry, and operator exception paths as new workflow states are introduced.
2. Broaden workflow/container failure drills beyond the current worker/server/PostgreSQL restart paths into host crash shapes, API process crash after durable ledger/outbox commit, and deployed post-broker-ack outbox worker failure.

This would not retire Node by itself, but it would close the largest remaining control gaps after the health, structured-error, outbox-state, Redpanda delivery, signed-JWKS auth, workflow-state, live Temporal, and Next shell/API-backed command parity slices.
